# PlatScope Reward OCR

Изолированный Windows-процесс распознавания экрана наград реликвий.

- захватывает только клиентскую область окна Warframe;
- использует геометрию экрана наград, цветовые темы и Tesseract по подходу WFInfo;
- при живом сканировании держит один экземпляр Tesseract, сравнивает несколько кадров и возвращает лучший результат по подходу WFHelper;
- получает маркеры экрана наград в реальном времени через Windows DBWIN; `EE.log` используется только как резервный источник;
- принимает каталог предметов через `stdin` и возвращает только JSON через `stdout`;
- поддерживает `imagePath` для воспроизводимых тестов без запущенной игры.
- автоматически читает масштаб интерфейса из локального `Warframe/EE.cfg`.
- хранит русскую модель Tesseract внутри OCR-модуля и при первом запуске извлекает её в локальный кэш PlatScope; расположение ресурсов установщика на работу не влияет;
- сопоставляет распознанный текст только с русскими названиями из локального каталога WFM; английские кандидаты в OCR не передаются.
- получает все известные торговые награды реликвий, даже когда полный рецепт их сета не поддержан; список реликвий из журнала лишь меняет приоритет, но не отсекает награды остальных игроков;
- не подменяет парное оружие одиночным (например, Акбронко / Бронко), если нужного предмета нет в каталоге; при равнозначных совпадениях разных предметов сохраняет неопознанный текст.
- проверяет имя перед словом «Прайм» отдельно от общих слов детали: обрывок «Прайм: Каркас» не превращается в каркас Эша. Незавершённый кадр может быть дополнен следующим кадром с читаемым именем.

Процесс ничего не пишет в память Warframe и не отправляет снимки в сеть.

В диагностике приложения доступна запись всех принятых сообщений Warframe через
тот же слушатель DBWIN, с предпросмотром и отметками. Запись выключена по умолчанию.
Инструкция и формат файла: [Запись DBWIN](../../docs/DBWIN_CAPTURE.md).

## Локальная проверка без игры

```powershell
dotnet build 'apps/reward-ocr/PlatScope.RewardOcr.csproj' -c Debug
& 'apps/reward-ocr/bin/Debug/net8.0-windows/win-x64/platscope-reward-ocr.exe' --self-test-russian
```

Самопроверка включает экраны на 2, 3 и 4 награды, двухстрочное название Акбронко,
пары Акбронко / Бронко, Аклекс / Лекс, Аквасто / Васто, Акмагнус / Магнус,
неполный каталог, неоднозначные совпадения, перестановку кандидатов и короткое
название «Лок». Успех — код завершения `0`; ошибка — `3` и объяснение в `stderr`.
Также проверяются двухстрочный Ревенант рядом с Эшем и Банши, потерянная первая
строка, ошибки в слове «Прайм» и восстановление имени по следующему полному кадру.
Та же проверка автоматически выполняется при подготовке OCR для релиза.

Для проверки конкретного полного снимка окна передайте его путь в `imagePath`
JSON-запроса вместе с каталогом. Фрагмент экрана нужно предварительно поместить
на холст исходного размера: иначе геометрия областей наград не совпадёт.
Проверочные снимки и личные данные игроков в репозиторий не добавляются.


## Запуск после готовности наград

`OpenVoidProjectionRewardScreen` означает начало открытия экрана. В записи от 12.09.2026 до `ProjectionRewardChoice.lua: Got rewards` проходило 5,56–5,76 секунды. Поэтому ранний маркер больше не запускает OCR: его окно повторов заканчивалось раньше появления карточек, а cooldown слушателя подавлял настоящий сигнал готовности.

DBWIN запускает распознавание по `Got rewards` или `Missing icon data!`. Резервный разбор EE.log также игнорирует раннее открытие. Дубли готовности по-прежнему подавляются; закрытие экрана сбрасывает состояние для следующего раунда. Визуальное обнаружение сохраняется.

Целевая проверка запуска без игры: `--self-test-trigger`. Она проверяет ранний маркер, готовность, дубли и следующий раунд. Скриншот пользователя с двумя наградами (Бёрстон Прайм и Когаке Прайм) распознан установленным и исправленным помощниками с уверенностью 1,0. Сам скриншот в Git не добавлен.

## Выбор реликвии до миссии и между раундами

Тот же слушатель DBWIN сообщает об открытии `ThemedProjectionManager.swf`.
Загрузка файла через `ResourceLoader` или `Spot-loading` не считается открытием
окна и не определяет собственную реликвию: игра загружает также предметы отряда.
Миссия определяется по JSON `Set squad mission`, `Requested mission` и
`Client loaded`; название берётся из `Cached mission name`. Уровень `VoidT6`
означает Омния: выбор отдельной Акси не сужает эру миссии до Акси.
Связь уровня 6 с Омния подтверждена локальными данными разрывов и моделью
поставщика; реальная запись выбора на Омния ещё не воспроизводилась.

В русской записи игры собственное имя находится в диалоге
`Вы уверены, что хотите взять Реликвия ... с собой на миссию?`.
Только следующий `Dialog::SendResult(4)` подтверждает выбор. Другой диалог,
отказ и истечение 30 секунд аннулируют ожидаемое подтверждение. Если улучшение
не названо явно, помощник возвращает `refinement: null`: отсутствие слова
«Сияющая» не доказывает, что реликвия нетронутая.

До диалога отдельный поток читает русский заголовок подготовки,
строку текущей эры и правое название реликвии. Он передаёт `browse`
с источником `screen_ocr`, не подтверждая выбор и не списывая количество.
`screenEra` отражает вкладку просмотра; известная `era` миссии сохраняется.
Проверка выполняется примерно через 700 мс после предыдущего кадра
только при открытом менеджере и активной игре; стартовое восстановление
по уверенно распознанному заголовку проверяется не чаще раза в две секунды.
После подтверждения или закрытия поздний кадр отбрасывается по поколению.
Три потерянных заголовка после успешного распознавания закрывают подсказку.

Событие `type: relic_selection` содержит `phase`, `sessionId`, `selectionId`,
`era`, `screenEra`, `relicName`, `refinement`, сведения о миссии, `source` и `reason`.
Фазы `open`, `selected`, `closed`, `mission`, `reset` и `reward` описывают
выбор и видимость. Фаза `visibility` дополнительно содержит `foreground`:
она меняется при уходе из Warframe и возврате, включая закрытие игры.
Смена процесса создаёт новую сессию; повторные сигналы не подтверждают выбор
или расход ещё раз.

Фаза `opened` требует подтверждённого собственного выбора и пары сообщений:
`gets reward /Lotus/StoreItems/...`, затем `Sending reward info ... to host!`
для одного игрока в пределах 10 секунд. Идентификатор игрока остаётся только
во временном внутреннем сопоставлении и не входит в событие. `Got rewards`
самостоятельно не доказывает раскрытие собственной реликвии: игрок мог не
собрать реагенты. При отсутствии указанной пары, в том числе у хоста,
помощник не предполагает расход; количество уточняется свежим инвентарём.

Эта последовательность выбора и раскрытия подтверждена локальной записью
от 12.09.2026. Критическая самопроверка `--self-test-trigger` дополнена отменой,
переключением диалогов, неизвестным улучшением, чужим идентификатором, дублями,
устаревшими событиями, сменой процесса и видимостью. Проверка выполняется
без игры, захвата экрана и управления окнами.

На предоставленном снимке подготовки от 03.10.2026 команда
`--scan-relic-preparation <путь-снимка>` определила эру `neo` и имя
`Neo T11`, сохранив неизвестное улучшение. Это проверка конкретного файла,
а не визуальный тест бокового окна в живой игре. Полное описание:
[Подсказка выбора реликвии](../../docs/RELIC_SELECTION.md).
