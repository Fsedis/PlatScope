# Производительность

## Бюджеты и границы

- запуск сначала читает локальную SQLite/LKG и не ждёт сеть;
- поиск выполняется в SQLite по нормализованному `search_text`;
- Market Browser запрашивает 60 строк, абсолютный предел service API — 100;
- история возвращает до 90 компактных дневных точек только выбранного `MarketVariantKey`;
- сетевые refresh и live-запросы выполняются вне UI thread;
- background bulk scheduler проверяет срок LKG раз в пять минут, но скачивает данные только после настроенного интервала 1–24 часа;
- входные документы и HTTP bodies имеют явные ограничения размера.

## Большие списки

UI намеренно не получает тысячи рыночных строк одновременно. Ограниченное окно сохраняет семантическую таблицу, доступную сортировку и предсказуемый размер IPC DTO. Виртуализация нужна только перед появлением режима, который увеличит окно результата примерно на порядок; лимит нельзя снимать раньше неё.

Inventory и Sell Now показывают персональные строки текущего snapshot, а не весь каталог. При росте реального пользовательского списка до тысяч строк сначала нужно измерить DOM/layout на репрезентативном snapshot, затем добавить windowing с сохранением keyboard navigation и screen-reader semantics.

## Автоматические проверки

`platscope-storage::tests::local_search_stays_bounded_with_thousands_of_items` создаёт офлайн-каталог и snapshot из 4 000 вариантов. Он проверяет, что запрос по множеству совпадений возвращает ровно bounded-окно из 61 строки не дольше 250 мс. На контрольном Windows-запуске запрос занял 3 мс; временной порог оставлен заметно шире, чтобы не создавать flaky CI.

Production smoke-test дополнительно измеряет полный `MarketBrowserService`, включая Pricing Engine. На snapshot из 3 840 предметов и 13 222 записей запрос `nyx prime` занимал 9 мс на контрольной машине.

Временные числа являются диагностикой конкретного запуска, а не обещанием одинаковой задержки на любом устройстве. Инварианты теста — ограниченный результат, отсутствие сетевого доступа и отсутствие загрузки всего каталога во frontend.
