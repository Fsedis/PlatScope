# Источники и обновление данных

## Матрица источников

| Данные | Источник | Назначение |
| --- | --- | --- |
| текущий bulk-снимок и история | `relics.run` | закрытые сделки, объём и медианы точных вариантов |
| резервный bulk-снимок | `FrameForgePricing` | fallback при недоступности основного снимка |
| каталог, предложения, профили и аккаунт | Warframe Market v2 | русские и английские имена, изображения, лучшие предложения, участники рынка, свои продажи и покупки |
| игровые определения | `WFCD/warframe-items` | комплекты, реликвии, дукаты, моды, изображения частей и требования мастерства |
| публичные ротации | `api.warframestat.us` | Баро, Стальной путь, идентификатор текущей Ночной волны и открытые заказы |
| точный инвентарь и Нора | Digital Extremes `inventory.php` и `getVendorInfo.php` | owned-количество, ранги, сборки, валюты и актуальный ассортимент |
| сделки и экран наград | локальные DBWIN и `EE.log` | триггеры OCR и подтверждённые торговые события |

## Правила доверия

- У каждого HTTP-источника собственные transport DTO, лимит ответа, parser и health-запись.
- Данные разных bulk-провайдеров не смешиваются внутри одного снимка.
- Внешнее display name не сохраняется как canonical key. Связь строится по ID/slug и точным измерениям варианта. Исключение — награды заказов: публичный Worldstate не отдаёт ID предмета, поэтому применяется только точное регистронезависимое совпадение английского имени с текущим каталогом; нечёткие совпадения запрещены, а нераспознанная награда остаётся без цены.
- Невалидный ответ не заменяет предыдущий валидный LKG.
- Отсутствующая цена хранится как `None`, а не как `0p` или выдуманный минимум.

## Рыночные цены

Основной daily URL:

```text
https://www.relics.run/history/price_history_YYYY-MM-DD.json
```

Поиск свежего снимка идёт назад не более чем на пять UTC-дней. История до 90 дней загружается инкрементально: сервис запрашивает только пропущенные даты и не скачивает уже сохранённый день повторно.

FrameForge используется только как целый резервный price snapshot:

```text
https://raw.githubusercontent.com/WyrmStudios/FrameForgePricing/main/price_history_latest.json
```

Bulk-набор не содержит надёжного платформенного измерения и поэтому применяется только к PC. Для другой платформы приложение не показывает PC-оценку как её цену.

### Статистика объявлений

Недельные мини-графики всех объявлений читают локальную историю одним пакетным запросом. Для раскрытого предмета доступны 7, 30 и 90 дней. Сопоставление учитывает точные slug, платформу, ранг, заряды, подтип и звёзды; данные других вариантов не подставляются. Полная дата архива и время проверки текущих предложений показываются отдельно.

В сводке строки сравниваются последние семь завершённых UTC-дней с предыдущими семью. Цена периода — медиана дневных медиан, а не медиана всех отдельных сделок. Процент изменения цены доступен только при наличии цены во все дни обоих периодов. Средний дневной объём — сумма исходного `closedVolume` за семь дней, делённая на семь; при пропусках среднее не рассчитывается, а сравнение объёма требует обеих полных недель. Сравнение с нулевой базой не превращается в бесконечный процент.

`volume` описывает закрытые сделки WFM, а не все обмены Warframe, уникальных покупателей или достоверное число проданных штук. Размер каждой исторической партии неизвестен: объём не умножается и не делится на `perTrade` текущего объявления. Отсутствующая дневная запись — пропуск. Ноль старого кэша без признаков закрытых сделок также не считается подтверждённым нулевым спросом; разрыв сохраняется на графике.

## Warframe Market

Каталог и текущие предложения запрашиваются через v2 API с `Language: ru`. В базе хранятся canonical slug, русское и английское имя, локализованное изображение. Ссылка предмета ведёт на `https://warframe.market/ru/items/{slug}`.

Запрос `/v2/orders/item/{slug}/top` получает до пяти лучших предложений с каждой стороны. После ответа PlatScope оставляет видимые объявления игроков в игре и повторно сверяет платформу, crossplay и вариант предмета. Счётчик — размер этой выборки, а не весь рынок. Цена за партию сопровождается `perTrade`; ориентир за единицу имеет отдельную подпись. Отсутствие предложений не означает нулевую цену.

Из того же ответа сохраняются необязательные имя, slug, репутация и ID объявления. Дополнительный запрос на каждого участника не нужен. Профиль открывается по возвращённому slug с фиксированным адресом WFM. Шаблон сообщения с английским названием, вариантом и ценой копируется локально; приложение не отправляет сообщение игроку.

Токен подключённого аккаунта хранится в Windows Credential Manager. Свои продажи и покупки читаются через `/v2/orders/my`. Создание, редактирование и удаление требуют явного действия пользователя; индивидуальное переключение показа меняет только `visible`. Новая заявка покупки сохраняет точный вариант из поиска и перед отправкой повторно проверяет аккаунт и наличие дубликата. Баланс платины не читается, оплата и обмен через API не выполняются.

Для выбранных объявлений показ меняется адресно, для всех объявлений текущего типа используется `/v2/orders/group/all` с `type: sell` либо `buy`. Перед записью приложение сверяет подтверждённое состояние; изменение состава или значимых полей останавливает устаревшее действие. Проверка и запись защищены общим замком операций аккаунта от одновременного локального учёта продажи. Это не серверная транзакция с чужими клиентами: WFM не предоставляет условную запись по версии. После неопределённого сетевого результата состояние сначала перечитывается.

Все клиенты WFM, включая поиск профиля, используют общий интервал не менее 400 мс между запросами. Исследованный официальный контракт, доступные методы и ограничения собраны в [аудите API](WARFRAME_MARKET_API_AUDIT_2026-09-06.md).

### История сделок и профили партнёров

История пользователя берётся из подтверждённых событий `EE.log` и локальной БД, а не из рыночной статистики. Экран читает до 1 000 последних событий; фильтры и CSV работают по этому набору. CSV сохраняется на компьютере, содержит обе стороны обмена и защищает текстовые поля от выполнения формул при открытии в таблице.

В игровом журнале есть имя партнёра, но нет WFM slug. Документированного поиска профиля по игровому имени в v2 нет. PlatScope проверяет кандидат через `GET /v2/user/{slug}` и открывает возвращённый адрес только при точном регистронезависимом совпадении `ingameName`. Похожие имена и имена с удалённым суффиксом не принимаются. Если игровой ник отличается от адреса профиля, автоматический переход может быть недоступен; это не доказательство отсутствия человека на WFM.

Отзыв пользователь оставляет на открытой странице профиля. Приложение не отправляет отзывы и не заменяет историю игровых обменов историей закрытых объявлений WFM.

## WFCD

Метаданные игры обновляются независимо от цен и атомарно сохраняются отдельным LKG. Из них берутся:

- состав и количество частей Prime-комплектов;
- таблицы наград реликвий и вероятности refinement;
- дукаты, mastery rank и Riven disposition;
- русские названия модов и точные изображения компонентов;
- правила растворения мистификаторов и доступные наборы.

Riven disposition является характеристикой оружия и не превращается в цену уникального Riven roll.

## Инвентарь и точная Ночная волна

Read-only scan запускается вручную или автоматически после событий игры, если включено автообновление. Из памяти процесса извлекается краткоживущая session info, после чего Rust-клиент запрашивает inventory endpoint DE. Отдельное задание `getVendorInfo.php` запускается только для отсутствующего/просроченного ассортимента Норы. Реквизиты извлекаются заново для каждого задания и после завершения обнуляются.

Публичный Nightwave endpoint определяет текущий season tag и ограничивает срок кэша концом сезона. Ассортимент и цены Норы считаются подтверждёнными лишь при успешном ответе Digital Extremes и действуют до указанного expiry. Просроченный ответ не продлевается за счёт срока отдельных товаров. При ошибке Ночная волна исключается из расчёта, а не угадывается по статическому списку.

## Открытые заказы

С 7 сентября 2026 игровые события и заказы имеют общий резервный загрузчик DE и
сохраняемый кэш заказов. Причина сбоя единственного источника, правила выбора ротаций,
ограничения и команды проверки описаны в [разборе восстановления](WORLDSTATE_RECOVERY_2026-09-07.md).

Worldstate `syndicateMissions` отдаёт активные заказы Цетуса, Фортуны и Некралиска, уровни противников, этапы и шансы наград. Награды Заримана и Кавии в публичном списке сейчас отсутствуют и поэтому не подменяются статической таблицей.

Ожидаемая платина полного заказа считается как сумма `шанс на этапе × количество × ориентир продажи`. Четыре опубликованные таблицы разворачиваются по правилам открытых заказов: первый этап; общая таблица второго и промежуточных этапов; отдельный четвёртый этап пятиэтапного заказа; финальный этап. Поэтому для заказов из трёх, четырёх и пяти этапов используются соответственно схемы `1 → 2 → финал`, `1 → 2 → 2 → финал` и `1 → 2 → 2 → 4 → финал`. Для нестандартных заказов, например некоторых хранилищ Изоляции, каждая опубликованная таблица учитывается один раз без выдуманного повторения.

Слабый ценовой сигнал получает консервативную скидку 30% в итоговой оценке. Если одна награда встречается на нескольких этапах, вероятность получить её хотя бы один раз считается отдельно и не складывается выше 100%. Непродаваемые и нераспознанные награды показываются без цены и не входят в платиновую оценку. Бонусные награды и время прохождения пока не учитываются.

## Локальные сигналы игры

`EE.log` читается только с текущей позиции и не изменяется. Торговый диалог ограничен timeout и становится событием лишь после success-маркера. DBWIN используется как быстрый сигнал экрана наград; `EE.log` остаётся резервом.

OCR получает каталог русских названий из локального LKG. Захваченные изображения не сохраняются и не отправляются внешним сервисам.

## Частота обновления

- market LKG: проверка при запуске и каждые пять минут, реальная загрузка только после истечения настроенного интервала;
- live quote: короткий TTL, по умолчанию 90 секунд;
- история: до семи отсутствующих дней за один фоновый проход;
- WFCD: раз в сутки либо вручную;
- открытые заказы: при входе в раздел, повторный запрос не чаще раза в пять минут либо явно по кнопке;
- инвентарь: по кнопке либо после сохранения/перехода локации в `EE.log`, с объединением событий и минимальным интервалом 30 секунд для фоновых чтений;
- точная Нора: один успешный запрос на срок ротации, затем кэш SQLite до серверного `Expiry`; при сбое повторы с растущей паузой 1/5/15/60 минут;
- сделки и награды: локальное наблюдение во время работы приложения.

Для каждого провайдера сохраняются `last_attempt`, `last_success`, безопасный код ошибки, задержка и число последовательных сбоев. Raw response и секреты в диагностику не входят.
