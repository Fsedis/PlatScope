## Точная награда

Строка 3002 после удаления идентификатора:

```text
1298.430 Sys [Info]: VoidProjections: [игрок] gets reward /Lotus/StoreItems/Types/Recipes/Weapons/WeaponParts/PrimeFangHandle
```

Сопоставление с локальным каталогом даёт `fang_prime_handle`, **Клыки Прайм:
Рукоять / Fang Prime Handle**. Для поиска в каталоге нужно нормализовать префикс
`/Lotus/StoreItems/` в `/Lotus/`: каталог содержит
`/Lotus/Types/Recipes/Weapons/WeaponParts/PrimeFangHandle`.

Строка появилась за 918 мс до `Got rewards`. В журнале всего одна строка вида
`VoidProjections: … gets reward …`; следующие сообщения сообщают о получении
ответов других игроков, но не раскрывают названия их наград.

Этот предмет входит в Лит T14, выбранную перед миссией. С учётом роли клиента и
следующего `Sending reward info … to host!` это согласуется с наградой собственной
реликвии. Однако прямого сопоставления обезличенного идентификатора с локальным
игроком вне блока наград в этой записи не найдено.

Сообщение о выпадении предшествует экрану выбора. Его нельзя считать доказательством
того, какой предмет игрок выбрал в итоге, и нельзя на его основании автоматически
прибавлять предмет к инвентарю.

```text
VoidProjections: OpenVoidProjectionRewardScreenRMI

ProjectionRewardChoice.lua: Got rewards

```

От первого сигнала до `Got rewards` прошло 1,323 секунды. Ранний сигнал можно
использовать для подготовки процесса и движка, но не для окончательного чтения
названий: данные остальных игроков ещё поступают. `Client has reward info for all
players now` пришёл практически одновременно с текущим `Got rewards` и в этой
сессии не даёт выигрыша во времени сам по себе.

Экран закрывается через 15,005 секунды после `Got rewards`. Таймер из сообщения
позволяет учитывать срок выбора, но закрытие нужно отслеживать отдельным событием.
Четыре `Missing icon data!` появились в течение 2 мс после `Got rewards`; считать
их четырьмя отдельными экранами или безусловным признаком четырёх наград нельзя.

## Другие возможности и ограничения

| Возможность | Что подтверждено | Как использовать |

| Сохранение инвентаря | Начало операции и отдельный успешный callback | Различать «сохраняется» и «сохранено»; точнее выбирать момент обновления. |

| Фокус игры | `WM_ACTIVATEAPP 0/1` | Дополнительный сигнал видимости; проверка реального окна остаётся надёжнее. |

`OnInventoryResults, body size=720365` сообщает размер ответа, а не выводит его
содержимое: полного JSON инвентаря в этой записи не найдено. JSON миссии содержит
таблицу потенциальных наград, не фактический список полученных предметов.

Торговых операций в записи не обнаружено. Упоминания `VoidTrader` и
`PrimeVaultTrader` относятся к игровому интерфейсу торговцев, а не доказывают обмен
между игроками. Данных о выбранной финальной награде и всех четырёх вариантах нет.

В текущем коде часть сигналов загрузки, сохранения и синхронизации инвентаря уже
используется через `EE.log` (`inventory_refresh.rs`). Само их обнаружение в DBWIN
не означает новую отсутствующую функцию. Отдельный callback успешного сохранения
может уточнить существующий алгоритм.

Проверенные строки точной награды, готовности всех наград и JSON параметров миссии
есть и в локальном `EE.log` этой игровой сессии. Для дальнейшего исследования и
резервного разбора можно использовать оба источника; запись не доказывает, что
DBWIN содержит исключительно доступные только ему данные.
