# Исследование игровых данных в памяти — 12 сентября 2026

Этот документ описывает первоначальный исследовательский проход. Последующее внедрение в приложение: [конфигурации и запись памяти](MEMORY_RECORDING.md).

## Условия и границы результата

Пользователь подтвердил, что персонаж находится в Орбитере или хабе. Исследована память запущенного Warframe ограниченным чтением. Наличие объекта в памяти не подтверждает его актуальность, владельца или использование в текущей экипировке. Старые ответы и конфигурации могут сохраняться после выхода из отряда.

Использованы два отдельных исследовательских примера, не подключённых к фоновому сборщику приложения:

- `crates/platscope-readonly-scan/examples/memory_research.rs`: исследование JSON экипировки через существующий сборщик отряда.
- `crates/platscope-readonly-scan/examples/memory_fields.rs`: поиск значений по ограниченному списку имён JSON-полей.
- `crates/platscope-readonly-scan/src/research_schema.rs`: сохранение типов, размеров массивов и примеров разрешённых игровых значений. Произвольные строковые значения, имена конфигураций, идентификаторы предметов и учётные данные не выводятся.

Результаты локально: `target/memory-research-loadout-schema.json` и `target/memory-research-fields.json`. Это схемы с выборочными игровыми примерами, а не сырые дампы памяти. Отчёты не включаются в исходный код.

Последний проход по экипировке: 5 различных JSON, 402 пути полей, около 1,29 с. Последний поиск именованных полей: около 6,62 с, прочитано около 8124 МиБ с учётом перекрытия блоков. Это разовые замеры на текущем процессе, не обещание производительности.

## Что подтверждено

| Данные | Где обнаружены | Что можно сделать |
| --- | --- | --- |
| Осколки варфрейма | `Suits[].ArchonCrystalUpgrades`: массивы из 0, 4 и 5 элементов, цвет и выбранный эффект | Дополнять сохранённый билд составом осколков после проверки актуальности инвентаря |
| Заменённая способность | `Suits[].Configs[].AbilityOverride`: ресурс способности и `Index` от 0 до 3 | Показывать замену отдельно для каждой конфигурации |
| Ранги модов | Декодированный `UpgradeFingerprint.lvl`: встречены значения 1–10 | Восстанавливать ранги после сопоставления экземпляра мода с записью конфигурации |
| Случайные параметры | `UpgradeFingerprint`: `compat`, `buffs`, `curses`, `lvlReq`, `rerolls`, `pol` | Исследовать параметры разломов и оружия со случайными бонусами; числовые значения пока закодированы |
| Реликвия и уровень | `VoidProjection.ItemType`, `VoidProjection.Level` в JSON экипировки | Показывать реликвии отряда, затем связывать с таблицей наград и ценами |
| Фокус | `FocusAbility` в JSON экипировки | Дополнять описание билда после сопоставления пути с названием школы |
| Части усилителя | `OPERATOR[].ModularPartTypes`, массивы из трёх частей; отдельный `OPERATOR_ADULT` | Сохранять состав усилителя, различать комплекты оператора и скитальца |
| Колесо снаряжения | `Consumables`, `ExtraConsumables` | Подсказывать подготовку к миссии; наличие пути не подтверждает запас предметов |
| Внешность | Скины и цвета в JSON экипировки и конфигурациях инвентаря | Сохранять внешний вид вместе с боевым комплектом |
| Рейлджек | `CrewShipLoadOut`: корабль, оружие, компоненты, экипаж и роли | Отдельное описание комплекта Рейлджека |
| Гельминт | `InfestedFoundry`: поглощённые варфреймы, ресурсы, предложения усилений, незавершённый рецепт | Подсказки по подготовке сборки и доступности замен способностей |
| Кузница | `PendingRecipes`: найден массив из 14 записей, тип рецепта и поле даты завершения | Список изготовления и готовности после декодирования дат и проверки свежести |
| Усилители | `Boosters`: найден массив из 9 записей, тип и `ExpiryDate` | Подсказывать подходящий фарм после проверки времени окончания |
| Эволюция оружия | `EvolutionProgress`: тип оружия, `Rank`, `Progress` | Исследовать прогресс; выбранные варианты эволюций этим поиском не установлены |

Количество записей кузницы и усилителей не означает количество незавершённых изготовлений или действующих усилителей: даты не проверялись.

## Связь осколков и замен с конкретным варфреймом

Добавлен отдельный вывод `suitDetails`: тип предмета, схема осколков и замены с сохранением индекса конфигурации. Найдено 40 различных сокращённых представлений предметов. Это не подтверждённое количество уникальных экземпляров: представления не содержат идентификаторов, могут объединять одинаковые экземпляры или включать старые варианты.

Названия варфреймов сопоставлены с текущими локальными метаданными PlatScope.

| Варфрейм в найденной записи | Осколки | Пример замены |
| --- | --- | --- |
| Севагот Прайм | 4 | `RhinoRoarAbility`, `Index: 3` во всех трёх найденных конфигурациях |
| Висп Прайм | 5 | `HopliteBashAbility`, `Index: 1` в конфигурации с индексом 0 |
| Титания Прайм | 5 | `DevourerConsumeAbility`, `Index: 1` в конфигурации 0; `RunnerTransferAbility`, `Index: 2` в конфигурации 1 |
| Ревенант Прайм | 5 | `HopliteBashAbility`, `Index: 0` в конфигурации 0 |
| Вольт Прайм | 0 | `DevourerConsumeAbility`, `Index: 0` во всех трёх найденных конфигурациях |

Это подтверждает структурную связь внутри объекта инвентаря. Владелец и выбранная сейчас конфигурация отдельно не подтверждены. Индексы приводятся в исходном виде; соответствие кнопкам способностей нужно сверить в Арсенале.

В осколках встречены `ACC_BLUE`, `ACC_BLUE_MYTHIC`, `ACC_RED`, `ACC_YELLOW`, `ACC_YELLOW_MYTHIC`. Пути эффектов различают силу, длительность, скорость применения, максимальную энергию, начальную энергию, эффект энергетических сфер и скорость паркура. Отображаемые величины бонусов и соответствие разновидностей осколков требуют проверки по игровым данным. Сводная схема объединяет примеры эффектов и не сохраняет их покомпонентное соответствие цветам.

## Что относится к экипировке отряда, а что к инвентарю

Реликвии, Фокус, части усилителя, колесо снаряжения, внешность и сведения о Рейлджеке обнаружены внутри JSON того же формата, который читает текущий сборщик отряда. Чтобы показывать их у конкретного игрока, по-прежнему требуется однозначное сопоставление с событиями журнала. Пять найденных JSON не означают пять присутствующих игроков.

Подробные замены способностей и осколки варфреймов обнаружены в объектах `Suits` отдельным поиском по памяти. Нельзя автоматически приписывать их сопартийцам. Даже совпадение типа варфрейма недостаточно для такой связи.

Ранги и случайные параметры требуют ещё одного шага: связать ссылки в `Configs[].Upgrades` с экземплярами модов. Некоторые элементы уже являются ресурсными путями, другие представляют идентификаторы. Простое объединение списков модов и найденных рангов может создать неверный билд.

В `DATAKNIFE` встретились также пути модов Рейлджека. При дальнейшем расширении интерфейса нужно проверить классификацию этой группы: подпись «Паразон» не обязательно подходит каждому её элементу.

## Чего этот проход не установил

- Координаты ближайшей добычи, расстояние до Воки, редкие контейнеры рядом и гарантированное наличие скульптуры на карте.
- Текущую волну и актуальные награды миссии.
- Итоговые проценты бонусов разломов, оружия и компонентов Рейлджека из числового `Value`.
- Текущую активную конфигурацию и владельца произвольного объекта инвентаря.
- Полный состав любого чужого билда с рангами, осколками и заменой способности.

По ключам `CurrentWave`, `PlayerPosition`, `Pickups`, `InventoryChanges`, `MissionInfo`, `MissionRewards`, `missionRewards`, `RewardInfo`, `EvolutionChoices` совпадений не найдено. Это результат поиска конкретных имён JSON-полей в выбранных областях памяти, а не доказательство отсутствия соответствующих данных в процессе.

`missionType` вернул семь разных значений при нахождении персонажа в Орбитере/хабе. Это дополнительно показывает, почему найденную запись нельзя считать состоянием текущей миссии без привязки к событиям.

## Приоритет дальнейшей работы

1. Дополнить экипировку отряда реликвией, Фокусом и составом усилителя. Источник уже совпадает с используемым сборщиком; отдельно проверить актуальность реликвии при смене миссии и следующем выборе.
2. Исследовать подробное сохранение собственного билда: конфигурации, ранги, осколки и замены способностей. Сначала подтвердить сопоставление экземпляров и выбранную конфигурацию.
3. На основе состава билда и подтверждённого инвентаря показывать, каких модов и улучшений не хватает для повторения сохранённой сборки.
4. Для исследования миссий сравнивать короткие записи до загрузки, после появления на карте, до и после подбора, после возвращения. Проверять изменение поля на контролируемом действии, а не только наличие имени в памяти.

## Запуск и ограничения инструмента

Из корня проекта при запущенном Warframe:

```powershell
cargo run -p platscope-readonly-scan --example memory_research
cargo run -p platscope-readonly-scan --example memory_fields
cargo test -p platscope-readonly-scan --example memory_fields --example memory_research
```

Поиск именованных полей ограничен 30 секундами, 16 384 совпадениями и 32 различными значениями на ключ. Для `UpgradeFingerprint` и `Upgrades` достигнут предел разных значений. Отчёт не является исчерпывающим перечнем. `complete` означает завершение обхода выбранных областей в пределах времени; `capped` отдельно показывает ограничение конкретного ключа.

Выбраны доступные для чтения записываемые области до 512 МиБ, блоки по 4 МиБ с перекрытием 1 МиБ. Парсер ищет точную запись `"ИмяПоля":`; формат с пробелом перед двоеточием, другой регистр, сжатые данные и другие представления пропускаются. Чтение работающего процесса не является атомарным снимком.

Проверки: оба примера успешно запущены на текущем процессе; четыре запуска модульных тестов прошли (два общих теста в каждом примере): фильтрация персональных значений и сохранение связи конфигурации с заменой без идентификаторов.
