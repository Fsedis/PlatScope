# Возможности Warframe Market для PlatScope

Проверено 6 сентября 2026 года. Цель — удобное управление своими объявлениями, анализ спроса и цены, переход к предметам и участникам обменов. Проверялись публичные документы, исходный код PlatScope и запросы только на чтение. Аккаунт пользователя, объявления, сообщения и отзывы при исследовании не изменялись.

## Источники и актуальность

Основной источник — [официальный портал Warframe Market](https://docs.warframe.market/) и его [репозиторий 42bytes-team/wfm-docs](https://github.com/42bytes-team/wfm-docs). В документации и живом ответе `/v2/versions` указана версия `0.25.0`. Старые инструкции в Notion описывают `0.23.0`; при различиях приоритет у нового портала и фактического ответа сервиса.

API и WebSocket ещё не достигли версии 1.0. Официальный [раздел о состоянии интеграции](https://docs.warframe.market/docs/intro/) предупреждает о неполноте документации и прекращении поддержки v1. Отсутствие метода в новой документации не доказывает его отсутствие на сервере, но не позволяет обещать стабильную интеграцию.

## Управление объявлениями

Подтверждённые методы из [официального раздела Orders](https://docs.warframe.market/docs/api/orders/):

| Метод | Назначение в PlatScope |
| --- | --- |
| `GET /v2/orders/my` | Все свои продажи и покупки, включая скрытые. |
| `GET /v2/order/{id}` | Одно объявление. |
| `POST /v2/order` | Создать продажу или заявку на покупку. |
| `PATCH /v2/order/{id}` | Цена, количество, видимость, размер лота, параметры предмета. |
| `DELETE /v2/order/{id}` | Удалить без записи продажи. |
| `POST /v2/order/{id}/close` | Закрыть указанное количество; возвращает транзакцию. |
| `PATCH /v2/orders/group/all` | Общая видимость с обязательным для PlatScope ограничением `type: sell` либо `buy`. |

Записи требуют авторизации и подтверждённого аккаунта. Платина: 1–900000; количество: 1–9999; `perTrade`: 1–6 и делитель количества. Параметры ранга, зарядов, звёзд и подтипа допустимы только для соответствующих предметов. `/close` уменьшает остаток либо удаляет объявление целиком. Массовая видимость возвращает число `updated`.

В поиске предметов добавлена форма заявки покупки: точный вариант, цена за штуку, количество, видимость и общий итог. После явного подтверждения используется `POST /v2/order` с `type: buy`. Перед отправкой повторно проверяются аккаунт и дубликат точного варианта. Поиск не содержит надёжного признака `bulkTradable`, поэтому форма не предлагает произвольный размер партии и оставляет `perTrade` пустым. Существующие заявки покупки редактируются рядом с продажами; игровой инвентарь не ограничивает желаемое количество покупки.

В [Groups](https://docs.warframe.market/docs/api/groups/) подтверждены только виртуальные группы `all` и `ungrouped`. Создание пользовательских групп пока не опубликовано.

Что было в PlatScope до переработки: вход, свои объявления обоих типов, создание, редактирование, удаление и автоматическое закрытие однозначно распознанной игровой продажи. Проблема состояла преимущественно в доступности этих действий в интерфейсе.

Для нового экрана нужны компактные строки, независимые фильтры продаж и покупок, поиск на русском и английском, редактирование рядом со строкой, отдельный показ/скрытие и массовое действие только для выбранного типа объявлений. Для массового показа продаж недостаточно проверить каждую строку отдельно: два скрытых объявления могут претендовать на одни детали. Проверка должна учитывать одновременно будущую видимость и резервы полных комплектов.

В этой переработке добавлен клиент массовой видимости с обязательным типом объявления. Диалог передаёт снимок всех объявлений выбранного типа, включая уже видимые; серверный список сравнивается с ним до проверки запасов и непосредственно перед записью. Изменения при обработке игрового журнала сериализуются общим замком. Сервер не документирует условную запись по ETag: действия в другом клиенте между последним чтением и записью остаются внешней гонкой.

Редактирование и удаление из нового экрана передают `expectedOrder`: снимок именно той строки, которую подтвердил пользователь. Каждая запись повторно сверяет все её поля под замком аккаунта. Это защищает следующую строку массовой коррекции, если автоматическая продажа успела уменьшить остаток после общей предварительной проверки. Старые вызовы без нового параметра остаются совместимыми.

## Текущие предложения и участники

`GET /v2/orders/item/{slug}` возвращает видимые объявления пользователей, недавно посещавших сайт; офлайн-пользователи не исключаются автоматически. `/v2/orders/item/{slug}/top` возвращает до пяти покупок и пяти продаж пользователей в сети. Это ограниченная выборка лучших предложений, а не весь рынок. Варианты фильтруются по рангу, зарядам, звёздам и подтипу. [Контракт Orders](https://docs.warframe.market/docs/api/orders/)

Для честного интерфейса:

- Не называть длину `/top` количеством всех покупателей или конкурентов.
- Сопоставлять одинаковые варианты и размеры лота; цена за лот и цена за единицу — разные значения.
- Показывать дату проверки, статус пользователя и источник цены. Отсутствие предложений не равно нулевой цене.
- Сохранять `user.ingameName`, `user.slug`, `user.reputation` и `user.status` из уже полученного ответа. Дополнительный запрос на каждую строку для этих полей не нужен.
- Ссылку предмета строить из проверенного каталожного slug: `https://warframe.market/items/{slug}`; статистику — добавлением `/statistics`.

В существующем `WarframeMarketProvider` уже использовался `/top` с точными параметрами, но нормализация оставляла только предложения игроков в игре и отбрасывала имя/профиль. Любая подпись числа предложений должна учитывать это дополнительное ограничение.

В переработке имя, slug профиля, репутация и ID объявления сохраняются через provider → domain → `LiveOrderView`. Все поля необязательны: старый кэш или неполный ответ не порождает выдуманную личность. Ссылка строится из возвращённого slug, не из отображаемого имени.

По этим данным можно открыть профиль участника и скопировать подготовленное сообщение для игрового чата. Копирование выполняется локально, без обращения к API сообщений и без автоматической отправки. Если имя или английское название предмета отсутствуют, сообщение не составляется из предположений.

## Семь дней: цена и объём

Живой запрос [GET /v1/items/styanax_prime_set/statistics](https://api.warframe.market/v1/items/styanax_prime_set/statistics) с платформой PC вернул `statistics_closed` и `statistics_live`, окна `48hours` и `90days`. В закрытой дневной серии есть `datetime`, `volume`, `median`, минимальная и максимальная цена, цены открытия/закрытия, средняя и взвешенная цена; часть дополнительных показателей может отсутствовать. У нового предмета или варианта точек бывает меньше длины окна.

Актуальные v2-документы не дают замены этой серии. Поэтому не следует придумывать `/v2/statistics` или обещать поддержку v1 бессрочно. Для большого списка выгоднее использовать уже загруженный PlatScope дневной архив и локальную БД: в `MarketHistoryPoint` есть `closedMedian`, `closedVolume`, `sellMedian`, `buyMedian`, а хранение разделено по точному варианту предмета. Один сетевой запрос статистики на каждое объявление при каждом открытии вкладки не нужен.

Официальная [локализация WFM](https://github.com/42bytes-team/wfm-localization/blob/master/locales/en.json) называет показатель `Volume`, а транзакции — объявлениями, отмеченными купленными или проданными. Это не полная статистика обменов Warframe. Точное правило суммирования `volume` для штучных и пакетных сделок в актуальных публичных документах не определено.

Рекомендуемая подпись — **«Объём/день»**, пояснение: «Средний дневной объём закрытых сделок WFM за выбранный период». Нельзя без дополнительного подтверждения заменять её на «уникальных покупателей», «всех продаж в игре» или «проданных штук». `volume` нельзя делить либо умножать на текущий `perTrade`: историческая серия не содержит размер каждого лота.

Для семидневной сводки нужны две отдельные визуализации: линия дневной медианной цены и столбцы дневного объёма. Процент изменения цены рассчитывается между доступными сопоставимыми точками; изменение объёма — по явно указанным периодам. Если семи дней нет, показывать покрытие и пропуски, а не рисовать выдуманные нули. Дневные даты интерпретировать в UTC. Статистика до последней архивной даты и текущие предложения должны иметь разные подписи времени.

## Профиль партнёра и отзывы

[Users](https://docs.warframe.market/docs/api/users/) подтверждает публичные `GET /v2/user/{slug}` и `/v2/userId/{userId}`. [Модель пользователя](https://docs.warframe.market/docs/data-models/#user) разделяет `ingameName`, `slug`, платформу, совместимость crossplay и репутацию. Игровой ник нельзя без проверки объявлять slug профиля.

В истории PlatScope имя партнёра приходит из EE.log, а не из WFM. Корректный путь: прочитать кандидат профиля, проверить точное имя без учёта регистра и только затем открыть возвращённый slug. При отсутствии совпадения сообщить, что профиль не найден по этому нику. Не открывать похожего человека. Подтверждённый ID можно использовать для последующих обращений.

В опубликованном v2-контракте нет описанного поиска пользователей по нику, отправки отзывов или чтения всей истории игровых обменов. Поэтому кнопка партнёра открывает настоящий профиль WFM; пользователь сам оставляет отзыв на сайте. Автоматическая отправка отзывов и сообщений здесь не требуется.

Историю WFM и игровой журнал нельзя считать одним источником. Существующее автоматическое закрытие уже сверяет событие игры, состав, количество и цену и запоминает обработанный обмен. Отдельная кнопка «Продано» без связи с событием могла бы закрыть ту же продажу ещё раз, когда позднее придёт запись EE.log. Она не добавляется без устойчивого механизма устранения дублей. Уже есть повтор сопоставления необработанного события.

## Авторизация, статус и обновления в реальном времени

[OAuth overview](https://docs.warframe.market/docs/oauth/overview/) прямо сообщает: регистрация сторонних OAuth-клиентов пока не открыта. Для текущих интеграций остаётся вход v1. Наличие примера OAuth или описанного `clientId` не означает, что PlatScope может зарегистрировать клиент. Существующее хранение токена в защищённом хранилище ОС сохраняется.

Подтверждённый [WebSocket](https://docs.warframe.market/docs/websockets/overview/): `wss://ws.warframe.market/socket`, обязательный subprotocol `wfm`. Статус задаётся командой [@wfm|cmd/status/set](https://docs.warframe.market/docs/websockets/status-and-activity/) после авторизации и получения текущего серверного состояния. Значения: `online`, `ingame`, `invisible`; длительность — 60–21600 секунд. Статус связан с соединением и сроком действия. HTTP-метод изменения статуса в текущем контракте не опубликован.

Для корректного переключателя статуса потребуется постоянный WS-клиент с переподключением и синхронизацией серверных событий. Одноразовый HTTP-запрос или локальная надпись «В игре» не заменяют эту функцию.

[Subscriptions](https://docs.warframe.market/docs/websockets/subscriptions/) подтверждает поток новых видимых объявлений `@wfm|cmd/subscribe/newOrders` и событие `@wfm|event/subscriptions/newOrder`. Подписки на изменения конкретного предмета и профиля прямо обозначены как ещё не реализованные. Общий поток новых объявлений не позволяет надёжно поддерживать актуальное состояние своих остатков.

## Каталог и дополнительные возможности

[Manifests](https://docs.warframe.market/docs/api/manifests/) содержит:

- `GET /v2/versions`: версии коллекций; полезно обновлять каталог только при смене хеша.
- `GET /v2/items`, `/v2/item/{slug}`, `/v2/item/{slug}/set`: названия, картинки, допустимые параметры и состав комплектов.
- Справочники оружия и характеристик модов Разлома, оружия/эфемер/особенностей личей и сестёр.
- Миссии, локации и NPC.

Для текущей вкладки важны каталог, точные варианты и комплекты. Справочник модов Разлома не является готовым API их оценки или торговли контрактами. Опубликованный каталог также не даёт доступ к игровому инвентарю, балансу платины или выполнению обмена в игре. Проверка наличия предметов остаётся отдельной функцией PlatScope.

Профильные предпочтения, аватар, достижения и витрина описаны в документации, но не помогают управлять большим списком объявлений. Копировать весь сайт в эту вкладку не требуется.

## Ограничения запросов и проверка

[Общие правила API](https://docs.warframe.market/docs/rules/overview/) требуют обозначать приложение собственным User-Agent, использовать кэш и избегать лишнего опроса. Общий лимит — 3 запроса в секунду; ограничения могут меняться. Для поиска контрактов указаны более строгие ожидаемые пределы. [HTTP overview](https://github.com/42bytes-team/wfm-docs/blob/master/docs/api/overview.mdx) описывает ответы 429 и 509, заголовки `Language`, `Platform`, `Crossplay` и ошибки полей.

PlatScope уже имеет общий интервал 400 мс для публичного и авторизованного WFM-клиентов. Новые возможности используют тот же ограничитель. Каталог и история читаются локально; публичные предложения проверяются по необходимости. Записи нельзя вслепую повторять после тайм-аута: сначала нужно выяснить фактическое серверное состояние.

Во время аудита без авторизации проверены:

| Запрос | Результат |
| --- | --- |
| `GET /v2/versions` | Версия 0.25.0, хеш коллекции предметов. |
| `GET /v2/orders/item/styanax_prime_set/top` | По пять покупок и продаж; у участников есть имя, slug, репутация, статус и платформа. |
| `GET /v1/items/styanax_prime_set/statistics` | Закрытая и активная серии; почасовые и дневные точки, объём и медиана. |
| `GET /v2/user/fsedis` | Публичный профиль: `ingameName: Fsedis`, `slug: fsedis`; подтверждена форма ответа для проверяемого перехода из истории. |

Мутации аккаунта подтверждены документацией и локальными тестами сериализации/валидации. Реальные объявления ради проверки не менялись.
