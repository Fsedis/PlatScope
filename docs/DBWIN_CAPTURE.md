# Запись сообщений Warframe

В **Настройки → Открыть диагностику → Сообщения Warframe** можно начать
диагностическую сессию DBWIN. Запись выключена по умолчанию и не возобновляется
автоматически после перезапуска приложения.

1. Нажмите **Начать запись**. Игру можно запустить до или после этого.
2. Выполняйте действия в Warframe. Окно диагностики разрешается закрыть — запись
   продолжится, пока работает PlatScope.
3. Добавляйте короткие отметки: «открыл инвентарь», «начал миссию», «выбрал награду».
   Отметка получает время нажатия кнопки; она не определяет действие в игре автоматически.
4. Нажмите **Остановить запись**, затем **Открыть папку журналов**.

На экране видны последние 100 записей, новые сверху. Поиск применяется только к
этому хвосту. **Приостановить просмотр** замораживает список для чтения, но не
останавливает запись файла. Счётчики сообщений и отметок показаны отдельно.

## Файлы и ограничения

Каждая сессия — новый файл `warframe-dbwin-<время UTC>.jsonl` в подпапке
`diagnostics/dbwin` каталога данных PlatScope. Точный путь показан в интерфейсе.
Предыдущие сессии сохраняются в этой папке; после перезапуска предпросмотр старой
сессии не восстанавливается. Файлы открываются любым текстовым редактором.

Одна сессия ограничена 2 часами или примерно 100 МиБ. При достижении предела запись
останавливается; можно начать новую. При ошибке записи или завершении слушателя
показывается причина, уже записанная часть файла сохраняется. При обычном закрытии
главного окна журнал закрывается с записью причины. При аварийном завершении
последняя строка может оказаться неполной.

В файл попадают все **принятые** сообщения процессов Warframe, а не все игровые
события. Игровые сообщения, которые не отправляются в DBWIN, здесь недоступны.
DBWIN не хранит прошлую историю и не гарантирует доставку каждой строки. Другой
слушатель, например DebugView, может перехватывать сообщения; обнаруженное совместное
использование при запуске отображается предупреждением.

Сырые строки могут содержать ники, пути и другие личные данные. Они хранятся
локально, не добавляются в стандартный диагностический отчёт и не отправляются
в сеть. Перед передачей записи другим людям просмотрите её содержимое.

## Формат JSONL

Каждая строка — самостоятельный JSON-объект. Переносы внутри игрового сообщения
экранируются, поэтому одно сообщение всегда занимает одну строку файла.

| Поле | Смысл |
| --- | --- |
| `sequence` | Порядковый номер записи, включая отметки и границы сессии. |
| `receivedAt` | Время UTC получения сообщения OCR-помощником. Для отметок — время их добавления. |
| `elapsedMs` | Миллисекунды от начала записи до сохранения строки в приложении; при задержке передачи отличается от времени получения. |
| `kind` | `message`, `marker`, `session_start` или `session_stop`. |
| `processId` | PID источника для игрового сообщения; `null` для отметок и границ сессии. |
| `message` | Текст, декодированный как UTF-8. Исходные пробелы и переносы не удаляются. |
| `rawBase64` | Только для сообщений: оригинальные байты до завершающего нуля. Позволяют восстановить текст при другой кодировке. |

Первую строку помечаем версией формата 1. Отладочный буфер имеет ограничение размера;
файл сохраняет доступные слушателю байты и не может восстановить то, что игра или
канал не передали.

## Как исследовать новые события

Начните с отдельной сессии на один сценарий: вход в игру, открытие инвентаря,
миссия с реликвией, возвращение в орбитер, обмен. Повторите действие несколько раз
и добавляйте отметки. Сопоставьте строки с отметками и проверьте, повторяется ли
сообщение при том же действии и не встречается ли оно в других обстоятельствах.
Наличие строки в одной записи ещё не делает её надёжным сигналом для автоматизации.

После сбора можно сгруппировать сообщения по имени скрипта, найти идентификаторы
ресурсов и составить таблицу «сообщение → наблюдаемое действие → возможное применение».
Точные награды, изменения инвентаря и торговые события в DBWIN пока не подтверждены.

## Реализация и проверка

Запись использует существующий `DbwinRewardWatcher`. При запуске из приложения
параметр `--forward-debug-lines` добавляет события `debug_line` в его JSON-поток
после фильтра процесса и до разбора знакомых маркеров наград. В обычные логи
приложения этот поток не выводится. Родитель хранит строки только в активной сессии;
вне неё сообщения отбрасываются. Старый OCR-помощник без признака поддержки не
позволяет начать запись, чтобы не создавать пустой журнал с ложным статусом.

Локальные проверки:

```powershell
dotnet build 'apps/reward-ocr/PlatScope.RewardOcr.csproj' -c Debug
cargo test -p platscope-desktop --lib dbwin_capture
pnpm --dir apps/desktop check
```

В браузерном режиме разработки `?mock=1` доступны демонстрационные сообщения.
Параметр `mockDbwin` принимает `empty`, `unavailable`, `shared`, `error` для проверки
ожидания, отсутствующего слушателя, совместного доступа и ошибки создания файла.
