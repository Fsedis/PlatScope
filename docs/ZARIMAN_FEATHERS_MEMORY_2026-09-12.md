### Проверка двух исчезновений

**№ 1, native `0x26196ac1430`:** во втором снимке адрес читается, но vtable, metadata и handle обнулены. Исходный handle тоже указывает на ноль. Прежняя Zone продолжает существовать.

**№ 3, native `0x261ce40ba30`:** прежняя память перезаписана и больше не содержит структуру PickUp. Старый handle указывает на другой адрес; прежний Action-handle уже ведёт к DynamicProjector с `PickupGlowMaterial`. Повторное использование подтверждено непосредственно. Zone также остаётся валидной.

В сыром списке кандидатов второго снимка нет этих объектов даже среди не прошедших обратную проверку handles. Следовательно, отсутствие не вызвано фильтром. Мусор в бывших полях позиции у уничтоженного объекта не принимался за новые координаты.

У № 1 Action был пуст уже во время первого обхода. Это может быть переходное состояние, но его причина неизвестна. Поэтому формулировка «в начале было восемь доступных перьев, затем пользователь подобрал ровно два» не поддерживается записью.

## Типы, предметы и важное отличие от патронов

Метаданные перьев в этой записи:

| Тип | Метаданные |
|---|---|
| Common | `0x2611d4f4640` |
| Uncommon | `0x2611d4f4fe0` |
| Rare | `0x2611d4f4ed8` |
| Bounty | `0x2611d4f4d20` |

Проверяемая цепочка:

```text
PickUp
  +0x8   → метаданные → PickUpItemType=ZarimanDogTag…
  +0x428 → handle → Zone
  +0x528 → handle → отдельный Item → LocalizeTag=…/ZarimanDogTag…Name
```

Item раскрывается до `MiscItemBase → Item → Object`. Во всех 14 сочетаниях «снимок — размещённое перо» Zone и Item проходят обратную проверку, а названия согласуются с PickUpItemType.

**Отсутствие Action на +0x488 нельзя использовать как признак отсутствующего или уже подобранного пера.** У большинства размещённых перьев ссылка пуста при валидных Zone и Item. В предыдущей записи размещённые патроны и Circuits имели все три ссылки; это наблюдение не является универсальным правилом для всех PickUp.

У № 2 во втором снимке Action-handle изменяется на ненулевой, но его цель не проходит проверку метаданных и обратной ссылки. Ошибка сохранена явно: это не доказанное создание действия. В этой записи подтверждены только два Action у перьев в первом снимке и один во втором.

Унаследованный сценарий подбора называется `SyndicatePickupImpactMsg.lua / GiveItemToAll`. Это дополнительная причина не устанавливать авторство подбора по исчезновению одного клиентского объекта. Также из свойств следует `ImmediateCreate=0` у более конкретного предка и переопределение `AutonomousPickup`; поля необходимо применять по наследованию, а не складывать.

Полный инвентарь по сохранённому адресу тоже проверен. Счётчики Common/Uncommon/Rare/Bounty в обоих снимках одинаковы — 21/13/6/45. Они могут быть прежним синхронизированным состоянием аккаунта и не подтверждают изменение после подбора внутри миссии. Неизменность этого объекта не опровергает слова пользователя.

Среди новых частей нет совпадений с 27 ранее извлечёнными частями Corpus Outpost ни по адресам LevelInfo, ни по хешам геометрии, ни по геометрии вместе с размещением. Для дополнительной проверки координат рассчитаны расстояния до извлечённой поверхности. Семь из восьми перьев находятся в пределах 0,313 единицы, одно Uncommon — около 2,098. Предметы могут находиться вне поверхности перемещения или на другой высоте; ближайшая поверхность не подменяет реальную координату предмета. На рисунке отмечены исходные позиции, без привязки к ближайшему полигону.

## Проверка декодера

Процесс и база исполняемого модуля совпадают с предыдущей записью, но адреса экземпляров заново исследованы. Zstandard-словарь проверен по SHA-256 в обоих новых снимках; он совпал с прежним. Wrapper дополнительно проверяет статические binding-имена PickUp и TennoAvatar.

Для Item понадобилась поддержка ещё одной таблицы базовых метаданных `0x7ff66a02fb50`: сохранённый getter явно возвращает пустые свойства, а цепочка наследования продолжается. Это проверено дизассемблированием; код игры не исполнялся. Неизвестные таблицы не принимаются автоматически.

В рамках прохода типов разобраны 549 объектов с обратными handles и 280 сочетаний метаданных и снимков без ошибок исходного декодирования. Отдельная невалидная ссылка Action описана выше и не скрыта этим результатом.

## Что это даёт для приложения

Подтверждена основа поиска перьев по конкретному типу и месту. Для надёжного указателя в игре остаются:

1. Установить локального игрока и систему его координат в групповой миссии.
2. Читать текущие объекты из активного региона, а не считать каждый объект в полном дампе действующим.
3. Проверять доступность подбора и корректно обрабатывать уничтожение/повторное использование объектов.
4. Выбрать между простым направлением и маршрутом: второму нужны полнота геометрии и связи между частями.

В интерфейс эти результаты пока не внедрены. Все смещения и адреса относятся к исследованной сборке; переносимость не проверена.
