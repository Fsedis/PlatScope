# Обнаружение новых объектов через реестр региона

Исследование выполнено на локальных записях Warframe от 12 сентября. Игра не запускалась и не изменялась. Цель — находить поддерживаемые объекты в новых выделениях памяти, не перечитывая весь процесс и не сбрасывая существующую карту.

## Подтверждённая цепочка

```text
локальный Player ↔ Avatar ↔ MiniMap
Avatar +0x1E0 → контекст сцены
контекст +0x90 → handle → RegionMgrImpl
RegionMgrImpl +0x28 → handle контекста (обратная связь)
RegionMgrImpl +0x200 → массив handle объектов
handle → объект, объект +0x10 → тот же handle
объект +0x1E0 → тот же контекст сцены
```

Начальный объект выбирается по уже проверенной принадлежности локальному игроку и его мини-карте. Большинство объектов прежнего снимка не используется как доказательство текущей сцены.

Для исследованного профиля относительные адреса: таблица методов контекста `0x21CECC0`, его статические метаданные `0x28F21B0`; таблица методов RegionMgrImpl `0x21D29D8`, метаданные `0x28F3470`. Абсолютные адреса объектов не закреплены в приложении.

Заголовок массива: указатель `+0x200`, размер **в байтах** `+0x208`, ёмкость `+0x20C`. Один элемент — восьмибайтовая ссылка. Это подтверждено не только похожими данными:

- Метод №74, RVA `0xE03440`, читает `+0x208` и делит на 8.
- Метод №76, RVA `0xC66420`, возвращает начало из `+0x200` и конец как начало плюс число байтов из `+0x208`.
- Код обхода разыменовывает элемент как handle и проверяет наличие объекта. Пустые ссылки действительно встречаются; считать все позиции массива активными объектами нельзя.

Читатель проверяет фрагменты обоих методов, тип менеджера и обратные связи, а заголовок массива повторно читает после содержимого. До публикации новых точек повторно проверяется связь региона с исходным персонажем.

## Независимое сопоставление с полным разбором

| Запись | Снимок | Размер списка | Число позиций | Совпадения с известными объектами |
|---|---:|---:|---:|---|
| Зариман | 2 | 174 880 байт | 21 860 | 1283, включая все 6 перьев |
| Linea, Корпус | 3 | 106 440 байт | 13 305 | 1343, включая предметы подбора и заложника |
| Гринир | 3 | 133 136 байт | 16 642 | 67 из 67 сохранившихся объектов небольшой контрольной выборки |

Числа позиций не являются числом предметов на карте. Список включает другие классы, пустые и изменившиеся ссылки. В записях есть рассогласование времени чтения; неверные обратные ссылки отбрасываются. Другой массив менеджера, `+0x48`, не используется: его содержимое не соответствует искомому перечню размещённых объектов.

Поле экземпляра `+0x18` не используется как признак активности. Один исследованный метод дополнительно отбирает объекты по этому полю, однако у всех шести перьев оно равно `0xFFFFFFFF`. Переносить этот частный предикат на поиск предметов было бы ошибкой.

Офлайн-скрипты и подробные локальные сводки: `target/zone-discovery-20260913/`. Сырые записи не добавлены в Git.

## Реализация

`registry_discovery.rs` включён в секундный цикл после обновления связи локального игрока. При доступном реестре прежний обход блоков не запускается.

- Новые ссылки получают приоритет независимо от положения в массиве и его перевыделения.
- Прежние ссылки проверяются по кругу: ранее пустой handle может получить объект без изменения адресов массива.
- Очередь разделяет семьи из пользовательских фильтров и остальные поддерживаемые виды. Изменение фильтров пересчитывает приоритет накопленной очереди.
- Каждый экземпляр проходит существующий декодер типов, размещения и предметов, затем проверку принадлежности контексту. Координаты без подтверждённого объекта не публикуются.
- Накопленные объекты, геометрия, время начала сцены и её идентичность не заменяются. Поэтому добавление предметов не сбрасывает выбранную цель и положение камеры.
- При истечении бюджета незавершённая работа сохраняется. Ошибка или смена контекста не публикует неподтверждённую пачку и не очищает старую карту.

Пределы одного адресного прохода: 65 536 позиций списка (512 КиБ), 2048 проверок ссылок, 4096 ожидающих кандидатов, 4 МиБ всех запрошенных байтов и около 80 мс. Время проверяется между операциями; оно не прерывает уже выполняющееся системное чтение или распаковку свойств. Эти пределы относятся к обнаружению, отдельно от существующего обновления известных координат и состояний. Постоянной записи на диск нет.

## Ограничения

- Первоначальный поиск пока нужен для профиля, игрока и начальной геометрии. Последующим изменением добавлен его автоматический запуск по завершению загрузки локации в EE.log; ручная кнопка остаётся резервом. Подробности — в `MISSION_MAP.md`.
- Распознаются только уже поддерживаемые семейства и структуры. Реестр сам по себе не добавляет расшифровку новых игровых классов.
- Геометрия подгруженных комнат этим изменением не извлекается. Новые точки могут появиться за пределами первоначальной геометрии.
- Большая очередь разбирается за несколько обновлений. Частота опроса раз в секунду не означает, что все объекты большого реестра повторно проверяются за секунду.
- Если локальный игрок или реестр временно недоступны, работает прежний ограниченный поиск по известным блокам. Новые области он не покрывает.
- Наличие в реестре и принадлежность сцене не означают доступность для подбора. Проверка состояний предметов — отдельное исследование.
- Это изменения исходного кода, не опубликованный релиз. Живое прохождение с новой реализацией ещё не проверено.

## Выполненные проверки

Один критический автоматический сценарий проверяет появление объекта в новом выделении при пустом `discovery_ranges`, перевыделение массива, заполнение ранее пустого handle, сохранение прежней точки и отсутствие дубликатов. Он также отбрасывает чужой контекст, повреждённую обратную ссылку и чрезмерный размер массива. Попытка перечислить память в этом сценарии немедленно завершает проверку ошибкой.

Ручной интеграционный прогон на втором снимке Заримана оставляет от исходной сцены только подтверждённого локального персонажа. Адресный поиск восстановил **581 объект, включая 6 из 6 перьев**, без поиска по прежним блокам. Проверка прошла вместе с критическим сценарием; остальные 59 тестов библиотеки не запускались.

Архивный прогон занял 30,89 секунды циклов поиска, 869 вызовов; суммарно запрошено 156 344 176 байт, в основном из-за повторного чтения списка между короткими порциями работы. Это **не замер живой игры**: здесь выполняются дисковые чтения, проверка хешей и распаковка блоков; в неизменяемом архиве включён локальный кэш адресных результатов. Использовать число этих циклов как прогноз времени обнаружения в игре нельзя.

Для запуска ручной проверки используются переменные `PLATSCOPE_REGISTRY_ARCHIVE`, `PLATSCOPE_REGISTRY_SEQUENCE`, `PLATSCOPE_REGISTRY_SCENE` и тест `archived_mission_recovers_objects_from_only_the_local_player` с `--ignored`. Пути к частным архивам в исходниках не закреплены.

Дополнительная попытка проверить живой процесс ограничилась двумя прежними адресами Player. Полная действующая цепочка по ним не подтвердилась; новый глобальный поиск для замера не выполнялся. Живую задержку, появление новых предметов при прохождении и работу в отряде следует проверить на следующей миссии после установки сборки с этим изменением.
