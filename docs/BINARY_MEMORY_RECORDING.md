# Двоичная запись памяти для последующего исследования

В разделе **«Миссия»**, в раскрытии **«Запись для исследования после миссии»**, доступны два режима: **«Двоичные снимки памяти»** и прежний **«Только игровые поля»**. Они используют разные форматы и папки. Запуск живой карты эту запись не включает.

Двоичный режим сохраняет исходные байты, адреса областей и модули процесса. С ним можно после закрытия игры искать новые структуры, читать указатели и сравнивать состояния. Раздел **«Миссия» → «Сохранённая запись»** восстанавливает известные объекты и геометрию для поддерживаемой версии игры; см. [живую карту](MISSION_MAP.md).

## Как провести запись

1. Запустите тестовую сборку с этой возможностью и Warframe. Откройте **«Миссия» → «Запись для исследования после миссии»**.
2. Выберите **«Двоичные снимки памяти»** и предел размера: 8, 16 или 32 ГиБ. По умолчанию 16 ГиБ. Это максимальный размер сеанса, а не обязательный расход места.
3. В Орбитере нажмите **«Начать двоичную запись»**. Дождитесь первого снимка и состояния ожидания. Если запись завершилась по ограничению или снимок неполный, это будет указано.
4. Отправляйтесь на миссию. Автоматический обход начинается через 45 секунд после предыдущего. **«Снять сейчас»** доступно в промежутке между обходами.
5. Для проверки координат полезны снимки в одной комнате до и после перемещения, а затем в соседней комнате. Время начала и окончания каждого обхода сохраняется. Сам обход занимает время, поэтому движение внутри него может дать смешанное состояние.
6. После возвращения в Орбитер нажмите **«Снять сейчас»** и дождитесь готовности ещё одного снимка.
7. Нажмите **«Остановить и сохранить»**. Дождитесь завершения записи перед закрытием приложения. Откройте папку кнопкой **«Открыть папку записи»**.

Папка по умолчанию: `%LOCALAPPDATA%/PlatScope/diagnostics/binary-memory/warframe-binary-<UTC>/`. Для переноса или анализа нужна **вся папка одного сеанса**: снимки ссылаются на общий файл блоков и предыдущие индексы.

Запись начинается только явным действием пользователя и не возобновляется при перезапуске. Исходные байты могут содержать данные входа и переписку. Файлы не отправляются в сеть; не публикуйте их целиком. Для обмена результатами нужно извлекать отдельные проверенные игровые структуры.

## Ограничения и завершение

- Для запуска требуется минимум 3 ГиБ свободного места. Во время записи свободное место проверяется примерно раз в секунду; запись останавливается при остатке менее 2 ГиБ с запасом на текущий блок. Одновременная запись других программ может уменьшить этот запас.
- Максимальная продолжительность сеанса — 20 минут с завершением уже начатого обхода. Один обход ограничен 90 секундами и 24 ГиБ успешно прочитанных байтов. При достижении предела обхода сохраняется неполный снимок и запись завершается.
- Ограничение размера учитывает сжатые блоки и опубликованные индексы; под индекс зарезервировано до 64 МиБ. Служебный файл завершения может добавить несколько сотен байтов.
- Читаются доступные committed-области, включая данные и исполняемые модули. Области без доступа, guard, nocache, writecombine и execute-only не читаются. Их описания сохраняются в карте областей.
- `ReadProcessMemory` используется только для чтения. Игра не приостанавливается; её память не изменяется, код в процесс не внедряется. Обход может влиять на нагрузку и плавность игры.
- Чтение согласовано с существующими сканерами экипировки, конфигураций и исследовательских полей через общий замок. Ожидание замка можно отменить.
- Дескриптор процесса удерживается весь сеанс; фиксируется время его создания. Повторное использование того же PID другой игрой не смешивает запуски.
- Остановка между обходами оставляет последний готовый снимок. Остановка во время обхода сохраняет прочитанную часть с `complete=false`; ещё не прочитанные данные прошлого снимка не подставляются.
- Закрытие окна запрашивает остановку, но завершение процесса приложения может опередить запись текущего индекса. Поэтому для гарантированного завершения нужно использовать кнопку остановки и дождаться статуса. После аварийного выхода доступны ранее опубликованные индексы; незавершённый `.partial` игнорируется.

`complete=true` означает завершение предусмотренного обхода без ошибок списка модулей и пропусков чтения. Это не атомарный снимок всех данных игры и не доказательство актуальности каждого найденного объекта.

## Формат версии 1

| Файл | Содержимое |
| --- | --- |
| `session.json` | Время начала, PID, FILETIME создания процесса, ограничения, размер блока, порядок байтов и сжатие |
| `blocks.bin` | Последовательность независимо сжатых zlib-блоков |
| `snapshot-000001.json` | Первый индекс: карта областей, модули, успешно прочитанные блоки, пропуски и время обхода |
| `snapshot-000002.json` и далее | Карта областей и модулей этого обхода, изменённые блоки и удалённые адреса относительно родителя |
| `end.json` | Время и причина завершения, количество опубликованных снимков |

Размер блока — до 256 КиБ. Одинаковые байты имеют один SHA-256 и хранятся один раз в пределах сеанса, даже если встретились по разным адресам. Следующий индекс содержит только изменившиеся привязки адресов к блокам. Для поиска изменений сам процесс всё равно перечитывается: экономятся место и запись на диск, а не все операции чтения.

В индексе:

- `sequence`, `parent` — номер и родительский снимок;
- `started_at`, `ended_at` — временное окно обхода;
- `complete`, `reason`, `module_error` — качество и ограничения результата;
- `regions` — исходный адрес, размер, allocation base, защита, состояние, тип и признак разрешения чтения;
- `modules` — имя модуля, исходный адрес загрузки, размер;
- `changed` — исходный адрес блока → SHA-256, смещение в `blocks.bin`, размер сжатых и исходных данных;
- `removed` — адреса предыдущего снимка, отсутствующие в успешно прочитанной выборке текущего;
- `holes` — непрочитанные остатки блоков;
- `progress` — объём чтений и число сохранённых блоков/пропусков.

Числовые адреса и ключи `changed` представлены десятичными числами/строками. В исходных данных сохраняются исходные указатели x64 little-endian. Анализатор использует целые числа Python и не теряет точность 64-битных адресов.

Перед публикацией индекса блоки сбрасываются на диск. Индекс записывается в `.partial`, синхронизируется и переименовывается в `.json`. При аварии могут остаться неиспользуемые байты в конце `blocks.bin`; готовые индексы на них не ссылаются. Папка сеанса не открывается для продолжения после перезапуска.

## Разбор без игры

Утилита `scripts/inspect_memory_archive.py` использует стандартную библиотеку Python 3.10+. При чтении каждого блока проверяются границы, zlib и SHA-256. Она восстанавливает цепочку изменений, удаляет отсутствующие адреса и отказывается читать через пропуски.

```powershell
# Укажите папку конкретного сеанса, а не общую binary-memory.
$recordingPath = "C:\Users\Dmitrii\AppData\Local\PlatScope\diagnostics\binary-memory\warframe-binary-..."

# Все опубликованные снимки и их полнота.
python -X utf8 scripts/inspect_memory_archive.py "$recordingPath" --list

# Проверка всех блоков снимка 2.
python -X utf8 scripts/inspect_memory_archive.py "$recordingPath" --snapshot 2 --verify

# Произвольная двоичная последовательность; выводятся только адреса совпадений.
python -X utf8 scripts/inspect_memory_archive.py "$recordingPath" --snapshot 2 --hex "00 00 00 00 00 e0 5e 40"

# Поиск строки, если она нужна как зацепка для соседней структуры.
python -X utf8 scripts/inspect_memory_archive.py "$recordingPath" --snapshot 2 --text "/Lotus/"

# Прочитать 128 байтов по реальному адресу из этой записи.
python -X utf8 scripts/inspect_memory_archive.py "$recordingPath" --snapshot 2 --read 0x12340000 --length 128
```

Адрес в последней команде приведён только как пример. `--output` с `--read` сохраняет байты в новый файл без перезаписи существующего. Чтение за один запрос ограничено 16 МиБ. Поиск учитывает совпадения на границах соседних блоков, но не соединяет данные через непрочитанные участки. Для поиска указателя можно преобразовать исходный адрес в восемь байтов little-endian и использовать `--hex`.

## Проверки реализации

- Rust-проверка архива: сохранение произвольных байтов, сжатие, повторное использование одинакового содержимого, перечисление модулей собственного процесса.
- `cargo run -p platscope-readonly-scan --example binary_probe`: создаёт отдельный тестовый процесс, сохраняет два снимка с изменением числа, затем снимок с остановкой во время чтения и завершает процесс. Warframe этот пример не читает.
- Проверенный результат примера: два полных обхода примерно по 20,5 МиБ; первый индекс 164 блока, второй — 8 изменившихся. После закрытия процесса Python восстановил значения 123,5 и 456,25 и исходный указатель на них, проверил SHA-256 всех доступных блоков. Скорость и доля изменений Warframe этим примером не измерены.
- Python-тесты проверяют восстановление изменений, чтение через границы блоков, отсутствие подстановки устаревших данных, повреждённый SHA-256, игнорирование незавершённого индекса и некорректную цепочку родителей.
- Интерфейс проверен в фоновом встроенном браузере в широком и узком окне: запуск, ручной снимок, остановка, неполный результат, переключение режимов и ошибка при закрытой игре.
