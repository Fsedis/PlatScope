# Локальная сборка и подпись релиза

PlatScope собирается и проверяется на рабочей машине. GitHub используется только для хранения исходного кода и готовых файлов релиза. GitHub Actions не участвует ни в сборке, ни в подписи, ни в контрольной проверке.

## Что подтверждает доверие

В релизе используются два независимых механизма:

- подпись обновления Tauri подтверждает происхождение пакета для встроенного автообновления;
- SHA-256 в `SHA256SUMS.txt` позволяет вручную проверить целостность загруженного установщика.

Коммерческого сертификата Authenticode пока нет. Поэтому Windows SmartScreen может показать предупреждение «Неизвестный издатель», хотя встроенное обновление PlatScope проверяет подпись Tauri.

## Закрытый ключ

Закрытый ключ обновлений и его пароль хранятся только локально вне репозитория. Пароль защищён DPAPI текущей учётной записи Windows. Нельзя добавлять ключ или пароль в Git, GitHub, команды с выводом секрета, логи либо файлы релиза.

В `tauri.conf.json` хранится только публичный ключ. Он не является секретом и нужен установленному приложению для проверки обновления.

## Порядок выпуска

1. Обновить версию в корневом `Cargo.toml`, `apps/desktop/package.json` и `apps/desktop/src-tauri/tauri.conf.json`.
2. Локально выполнить форматирование, статические проверки, Rust- и frontend-тесты, сборку OCR и frontend.
3. Локально собрать NSIS-установщик с `createUpdaterArtifacts: true`, передав Tauri локальный закрытый ключ и пароль через переменные окружения только на время процесса сборки.
4. Локально сформировать `latest.json` и `SHA256SUMS.txt`.
5. Локально проверить совпадение версии приложения, Git-тега и `latest.json`, ссылку на установщик, непустую подпись и SHA-256.
6. Закоммитить и отправить проверенный код в `main`, создать тег `v<version>` на этом коммите.
7. Создать GitHub Release и загрузить готовые локальные файлы: установщик `.exe`, подпись `.sig`, `latest.json` и `SHA256SUMS.txt`.
8. Скачать опубликованные файлы во временный локальный каталог, повторно проверить хеш, версию, URL и подпись. Проверить, что `releases/latest/download/latest.json` отдаёт новый manifest.
9. Только после успешной проверки удалить все предыдущие GitHub Releases и соответствующие release-теги. Историю коммитов не переписывать.

Предыдущий релиз нельзя удалять, пока новый установщик и канал автообновления не подтверждены.

## Состав Windows-релиза

- `PlatScope_<version>_x64-setup.exe` — NSIS-установщик и пакет обновления;
- `PlatScope_<version>_x64-setup.exe.sig` — подпись Tauri;
- `latest.json` — manifest встроенного автообновления;
- `SHA256SUMS.txt` — SHA-256 установщика.

Версия и URL в `latest.json` должны указывать на этот же релиз. Подпись должна соответствовать именно опубликованному установщику.

## Ротация и компрометация

При подозрении на утечку публикация останавливается, ключ заменяется, скомпрометированный релиз удаляется из канала `latest`, а пользователям явно сообщается о ручном переходе на версию с новым публичным ключом.

Локальную резервную копию закрытого ключа нельзя удалять до проверки восстановления из защищённой копии: без старого ключа уже установленные версии не смогут принять обычное подписанное обновление.
