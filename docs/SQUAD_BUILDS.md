# Отряд и коллекция билдов

## Путь пользователя

Отряд → игрок → предмет → просмотр модов и мистификаторов → «Сохранить билд».
После миссии: сохранённые билды → поиск → заметка → список для повторения в Арсенале.
Приложение не применяет изменения в Warframe.

## Источники данных

- Существующий наблюдатель `EE.log` передаёт строки парсеру отряда. Отдельный слушатель
  DBWIN не запускается. Перед первым чтением экипировки парсер догоняет конец журнала,
  чтобы старые события входа/выхода не воспринимались как текущий отряд.
- `AddSquadMember`, `RemoveSquadMember`, `LeaveSquad`, `Logged in` и `Logout confirmed`
  формируют текущий состав. Платформа берётся из служебного символа имени.
- JOIN-сообщение содержит имя и длину JSON экипировки. После изменения состава или
  ручного запроса фоновый рабочий поток читает подходящие области памяти Warframe.
- Сигнатура начала JSON: `{"PlayerLevel":`. Принимаются завершённые строки с массивом
  `NORMAL`. Кандидаты сравниваются по содержимому, одинаковые копии объединяются.
- Из нескольких разных кандидатов одной длины никто не выбирается. Если одинаковая
  длина объявлена несколькими участниками, оба остаются без автоматической привязки.
  Единственное совпадение остаётся эвристикой — это явно сообщается при просмотре и экспорте.
- Своя экипировка в этом разделе не выбирается эвристикой «больше всего копий».
  Раздел предназначен для сопартийцев. Уже существующие «Надетые моды» продолжают
  использовать собственный инвентарь и конфигурации.

Парсер журнала и идея поиска заимствованы из
[synqark/warframe-peer-overlay](https://github.com/synqark/warframe-peer-overlay/tree/58d949745cd992ce27189d83b992dd4e23ad04e3),
Unlicense. Чтение памяти реализовано внутри существующей границы
`platscope-readonly-scan`; остальные части проекта остаются без unsafe-кода.

## Границы точности

12 сентября 2026 проверено чтение запущенной Warframe: найдено три различных
JSON-набора экипировки. У предметов присутствовали `ItemType`, `Level`, `LocTag`,
`WeaponUpgrades`, иногда `Polarized` и `FocusLens`. `WeaponUpgrades` содержал пути
косметики, модов и мистификаторов; рангов модов в проверенных элементах не было.
Полный сырой JSON не сохранялся и не выводился в журнал проверки.
Повторный запуск структурной проверки занял 1,88 секунды на рабочей машине.

Это проверка чтения и структуры, а не подтверждение всех привязок к сопартийцам
в реальной совместной миссии. Контрольный заход с известной экипировкой союзника
остаётся полезной проверкой перед релизом.

Порядок элементов `WeaponUpgrades` не выдаётся за порядок модов в Арсенале.
Неизвестные ранги, формы и поля не заменяются максимумом или нулём.
Косметика отделяется по известным типам и путям; неизвестное остаётся в раскрытии.
Классификация модов и мистификаторов использует торговый справочник, затем проверенные
семейства путей. Состав модульных предметов сохраняется отдельно.

Старые и новые версии могут сосуществовать в памяти. Смена объявленного размера
сбрасывает предыдущий снимок. Выход из отряда, перезапуск игры или журнала сбрасывают
текущие данные. Сохранение сверяет время снимка, чтобы обновление во время нажатия
не сохранило другой вариант незаметно для пользователя.

## Нагрузка и хранение

- Чтение выполняется по событию, не непрерывно. Одна фоновая задача за раз;
  максимум три попытки при отсутствии подходящего кандидата.
- Запросы объединяются на проходе, рабочий цикл — раз в три секунды.
- Обход ограничен 30 секундами; JSON — 1 МиБ, число различных кандидатов — 256.
  Читаются доступные области для данных размером до 512 МиБ, исключая защитные,
  некэшируемые области и буферы GPU с объединением записи. Блок чтения — 4 МиБ
  с перекрытием для целого JSON. Выход по лимиту возвращает ошибку, а не частичное
  «единственное совпадение».
- Поиск `memchr` оптимизирован и в dev-профиле: без этого проход по гигабайтам
  памяти в отладочной сборке превышал лимит времени.
- На диск по нажатию сохраняются только типизированные сведения о предмете,
  имя/платформа игрока, дата снимка, название и заметка. Сырая память, учётные данные,
  адреса и сетевые идентификаторы не сохраняются. Внешних запросов для этого раздела нет.
- Сохранённые билды: настройка `squad.saved_builds.v1` локальной SQLite-базы,
  включение сбора: `squad.enabled.v1`. Изменения коллекции атомарны на уровне SQLite.
- «Сохранить список в файл» записывает UTF-8-текст в `build-exports` внутри каталога
  данных PlatScope и показывает полный путь. Размер экспорта ограничен 256 КиБ;
  существующие файлы не перезаписываются.

## Проверки

Тесты покрывают неоднозначные размеры, неполные JSON, отсутствие выдуманных рангов,
сохранение неизвестных элементов, разорванные строки журнала, выход участника,
смену объявленного размера, сериализацию коллекции и текстовый экспорт.
Интерфейс проверяется в отдельном фоновом встроенном браузере на настольных размерах:
текущий отряд, сохранение, заметки, неизвестные элементы, пустые и ошибочные состояния.
Локально прошли 60 тестов desktop, 29 тестов границы чтения, 328 тестов TypeScript,
Clippy для всех целей обоих изменённых Rust-пакетов, форматирование и Svelte Check.
Проверены широкое и узкое настольные окна, сохранение заметки после перезагрузки,
экспорт (интерфейс и отдельный тест реальной записи UTF-8-файла), удаление тестового
билда, отсутствие игры, ошибка чтения и выключение сбора.

Отдельная отладочная сборка: `target/squad-preview/platscope.exe`. Рядом находится
каталог `resources`; запуск не требует dev-сервера. Перед запуском следует закрыть
другую копию PlatScope. Публикация релиза и замена установленного приложения не выполнялись.

Для локальной проверки структуры без вывода имён и сырого JSON:

```powershell
cargo run -p platscope-readonly-scan --example squad_probe
```

## Расширение: конфигурации и исследование миссии

Осколки и замены способностей разбираются из доступных полей экипировки и найденных конфигураций. Разбор расширен на все подтверждённые коллекции снаряжения: оружие, компаньоны, Паразон, Плексус, Рейлджек, оператор и Скиталец и другие категории. Конфигурации без подтверждённого владельца отображаются отдельно от отряда. Дополнительные поля сохраняются вместе с билдом; старые записи совместимы и показывают отсутствие данных.

Для полных объектов инвентаря ссылки конфигураций сопоставляются с `Upgrades` в пределах того же объекта. Поле ранга читается из `UpgradeFingerprint.lvl`. Прямой путь без ранга остаётся с неизвестным рангом; конфликтующие идентификаторы не разрешаются выбором случайной копии. Индексы, пустые и неразрешённые позиции сохраняются в `upgradeSlots`. Это порядок записи, а не доказанная сетка ячеек Арсенала. Сопоставление не переносится на JSON другого инвентаря или экипировку сопартийца.

Для модов разлома сохраняются только разрешённые поля: оружие, ранг, требование мастерства, преобразования, полярность и теги положительных/отрицательных свойств. Исходные значения не считаются процентами. Самостоятельный мод отображается, даже если не привязан к конфигурации; повреждённый fingerprint оставляет свойства неизвестными.

Запись перенесена в **«Миссия» → «Запись для исследования после миссии»**. Порядок работы и ограничения: [запись игровых полей](MEMORY_RECORDING.md), [двоичная запись](BINARY_MEMORY_RECORDING.md), [живая карта](MISSION_MAP.md).
