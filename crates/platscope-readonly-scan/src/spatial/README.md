# Ядро исследования сцены

`spatial` извлекает только проверенные пространственные объекты и геометрию. Публичные функции:

- `list_archive(path)` — завершённые снимки, даты, прочитанный объём и пропуски.
- `analyze_archive(path, sequence, cancel, progress)` — сцена из сохранённой записи.
- `analyze_live(pid, cancel, progress)` — полный ручной поиск в работающей игре.
- `refresh_live(pid, scene, cancel)` — быстрое обновление известных объектов и ограниченный поиск соседних объектов в уже подтверждённых пулах памяти.

У всех источников единый интерфейс `Memory`. Архив восстанавливается через родителей и `removed`; явные пропуски имеют приоритет над сохранёнными блоками. Чтение через границу соседних блоков поддержано. Размер, zlib и SHA-256 проверяются при загрузке каждого блока. Файлы индексов читаются через буфер, кэш хранит не более 16 распакованных блоков.

## Проверка версии

Поддерживается только исследованная структура игры. Адрес модуля берётся из источника. Проверяются размер модуля, два отпечатка машинного кода, таблицы и строки привязок `PickUp`/`TennoAvatar`. Относительные адреса применяются после этих проверок. Адрес словаря Zstandard извлекается через указатели из проверенного глобального контекста; постоянных адресов heap в коде нет. SHA-256 словаря обязателен. Неизвестная версия возвращает ошибку до построения сцены.

Свойства типов распаковываются как varint размера + Zstandard magicless со словарём текущего источника. Поддержаны три исследованные разновидности метаданных. Цепи ограничены по глубине и размеру, циклы и неизвестные таблицы отклоняются.

## Объекты

Тип объекта подтверждается метаданными и обратным handle. У предметов дополнительно проверяются отдельные `Zone` и `Item`; для перьев сравниваются `PickUpItemType` и `LocalizeTag` реального Item. Нулевые шаблоны исключаются. Пустой handle действия подбора не означает, что предмет уже подобран. Во внешней сцене доступность всегда `unknown`.

Матрицы объектов допускают ограниченный масштаб; оси после нормализации должны быть ортогональны. У неподвижных объектов XYZ должен совпадать с матрицей с допуском 0,02. У персонажей допускается отличие до 2 единиц между физической позицией и моделью — в проверенном архиве оно составляло около 0,15 при нормальной анимации. Принадлежность проверяется через двустороннюю связь TennoAvatar → LotusHumanPlayer → TennoAvatar. Базовая модель Excalibur в метаданных не используется как имя реально экипированного варфрейма.

Геометрия `LevelInfo` проверяется отдельно: ссылки, размеры массивов, индексы, конечные координаты, матрица, замкнутость каждого контура. Между частями уровня маршрут не строится. Соседство относится только к граням внутри одной части.

## Обновление живой карты

Полный поиск использует общий замок сканирования. `refresh_live` использует собственный read-only process handle и не берёт этот замок: он читает уже известные адреса. Периодического полного поиска в desktop-сервисе нет.

Идентичности объектов, исходный PID и время создания процесса хранятся внутри `Scene`, но не сериализуются. После загрузки сцены с диска живое отслеживание требует нового поиска. Перезапуск игры отклоняется. При изменении таблицы, типа, обратного handle, зоны либо Item объект удаляется из подтверждённой выборки без попытки определить, кто и почему его убрал.

Один `refresh_live` дополнительно просматривает два блока подтверждённых пулов, не более 512 КиБ. Новые кандидаты обрабатываются в пределах 80 мс; курсор обхода сохраняется. Новые области памяти и геометрия обнаруживаются при ручном полном поиске. Подгрузка комнат не инвалидирует сцену. Desktop-сервис останавливает её только по настоящему переходу FSM::LoadLevel или перезапуску журнала; новый полный поиск автоматически не запускается.

## Пределы

- Полный поиск: 24 ГиБ и 5 минут.
- Отмена проверяется между блоками, объектами и родителями индекса.
- Один произвольный read: до 16 МиБ; один сохранённый блок: до 256 КиБ.
- Индекс: 64 МиБ, цепочка индексов: 256 МиБ, до 1024 снимков.
- Кэш свойств: 32 МиБ; отдельное распакованное свойство: 1 МиБ.
- До 20 тысяч объектов, 256 частей геометрии и миллиона вершин.

Публичный JSON содержит только сцену, имена типов, ресурсы, адресные ключи и сводки проверок. Сырые свойства, содержимое словаря, данные входа и полные блоки памяти в него не включаются.

## Стабильность живых точек

`avatar` назначается только семейству TennoAvatar с согласованным владельцем. LotusNpcAvatar получает `npc` либо `hostage`, поэтому мобы не попадают в фильтр игроков. Смена Zone у движущегося объекта не меняет его идентичность. Неудачное чтение позиции не удаляет подтверждённого персонажа: `positionFresh=false` сохраняет последнее положение, а следующий успешный кадр возвращает свежие координаты. Две временные ошибки чтения заголовка допускаются; третья удаляет точку. Подтверждённая замена заголовка/handle удаляет её сразу.

## Игрок и родная мини-карта (0.1.79)

`context` адресно проверяет не более 16 персонажей. Единственный согласованный кандидат с Camera и MiniMap, ссылающейся обратно на его аватар, получает `players[].local=true`. При неоднозначности локальный игрок не выбирается. Дополнительно сохраняется ключ связанного LotusOperatorAvatar; переход управления в Оператора ещё не проверен на реальной записи.

Два массива MiniMap (записи 128 и 96 байт) должны содержать одинаковые Zone и границы XYZ. Длины выражены в байтах, ёмкость каждого массива ограничена 64 КиБ, число записей — 512. Использованная часть читается без захвата соседней памяти; заголовок массива проверяется повторно после чтения. Неудачный кадр оставляет прежние `zones` с `zonesFresh=false`. Текстуры не извлекаются, границы не выдаются за стены или готовый маршрут.

Эвакуация, терминалы и возможные места лута добавлены в первоначальный поиск и ограниченный поиск по известным пулам. Назначение проверяется по Tag/Script, размещение — по координатам и Zone. Возможные точки появляются как `lootspot`, никогда как подтверждённый предмет.
